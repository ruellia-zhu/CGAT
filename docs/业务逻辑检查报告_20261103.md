## 触发条件、证据与修复方向

### A01：两物种前缀冲突

- **触发**：两个物种的基因组分别放在不同目录，但都命名为 `genome.fasta`，且显示名留空。前缀由文件名推导，两个物种都得到 `genome`。前缀仅保留前 12 个字符，也增加了其他名称碰撞的可能性。
- **实测**：对两个物种各 8 个基因执行真实自动预处理，步骤报告成功；最终 `genome.gff` 仅包含 B1–B8，物种 A 的文件已经被物种 B 覆盖。
- **影响**：后续跨物种分析可能变成对同一套序列的分析；这是可能不报错的输入污染。
- **定位**：[前缀推导](E:/ComparativeGenomicsAnalysisTool/app/ui/analysis.py:227)、[生成规则](E:/ComparativeGenomicsAnalysisTool/app/ui/analysis.py:238)、[两物种共用输出目录](E:/ComparativeGenomicsAnalysisTool/app/wgdi/pipeline.py:278)。
- **建议**：内部文件前缀与显示名分离；固定使用独立物种键或生成唯一前缀；预处理前校验两侧输出路径不重叠。

### A02：旧缓存及半截比对结果复用

- **触发一**：先运行 DIAMOND，再切换到 BLASTP 或修改 evalue，点击“重新运行本步”。`run_step()` 先清除步骤详情，导致随后用于识别旧引擎的 `detail.engine` 消失；分块结果只凭文件非空直接复用。输入序列或阈值也没有缓存指纹检查。
- **实测**：先执行一次模拟 DIAMOND 比对，再切成 BLASTP、evalue 改为 `1e-20` 重新运行；总比对调用数仍为 1，第二次被标成成功，实际使用的仍是首次结果。
- **触发二**：比对报错或取消时留下一个非空 `.m8`。重试把它当成完成的分块。
- **实测**：模拟两条查询只写完 B1 后以退出码 1 失败；重试没有执行任何比对命令，却把仅含 B1 的部分结果合并并标记 `done`。
- **定位**：[重跑前重置状态](E:/ComparativeGenomicsAnalysisTool/app/wgdi/pipeline.py:77)、[旧引擎检查](E:/ComparativeGenomicsAnalysisTool/app/wgdi/pipeline.py:410)、[非空即复用](E:/ComparativeGenomicsAnalysisTool/app/wgdi/pipeline.py:428)。
- **建议**：缓存关联查询与数据库内容、引擎版本及搜索参数；分块写入临时文件，进程成功且格式检查通过后再发布完成标记；失败残留不能作为完成缓存。

### A03：设置变化未使已有结果失效

- **触发**：项目已有完成记录，修改“只保留染色体”、输入文件或参数，再点击“连续运行剩余步骤”。界面只更新项目属性，不计算受影响步骤；流水线仍按原 `done` 状态跳过。
- **实测**：把“只保留染色体”从开改为关，再连续运行预处理、比对和点阵图，三步全部跳过。
- **展示问题**：即使显式 `reset_from('prep')`，旧图仍留在文件夹；预览只根据文件存在与否展示，状态为 `pending` 时仍显示旧图且无过期提示。
- **定位**：[设置写回](E:/ComparativeGenomicsAnalysisTool/app/ui/analysis.py:721)、[续跑判断](E:/ComparativeGenomicsAnalysisTool/app/wgdi/pipeline.py:140)、[预览判断](E:/ComparativeGenomicsAnalysisTool/app/wgdi/preview.py:254)。
- **建议**：比较设置及输入指纹，按实际依赖关系使下游结果失效；预览和结果列表应校验结果所对应的运行版本。

### A04：跨物种 Ks 输入路径不可读

- **触发**：对不同物种运行 Ks。配置把两侧 CDS、蛋白路径用分号连接，而当前内置 WGDI 使用 `SeqIO.parse()` 直接读取单个文件名，不解析分号列表。
- **实测**：调用真实 `wgdi -ks total.conf`，出现 `FileNotFoundError`，目标文件名为 `../prepared/A.wgdi.cds.fasta;../prepared/B.wgdi.cds.fasta`。
- **影响**：当前默认生成的跨物种 Ks 配置无法完成计算。
- **定位**：[配置生成](E:/ComparativeGenomicsAnalysisTool/app/wgdi/conf.py:138)、[内置 WGDI 的读取方式](E:/ComparativeGenomicsAnalysisTool/dist/比较基因组分析/runtime/Lib/site-packages/wgdi/ks.py:59)。
- **建议**：合并两物种的已筛选 CDS、蛋白为各一个输入文件，并检查合并后的 ID 唯一性；交给 WGDI 单文件读取。

### A05：Ks 生命周期与完成判据

- **旧文件问题**：`reset_from()` 只清步骤元数据，旧 `.ks` 仍存在；配置随后按文件是否存在把它重新挂入块汇总。实测 Ks 状态为 `pending`，`[blockinfo]` 仍引用旧 `A-B.ks`。修改序列或算法后，WGDI 也会跳过旧文件中已经出现的 ID 对。
- **失败结果问题**：内置 WGDI 在单对基因的计算失败时可能返回空列表，而上层仅跳过 `None`，最终写出只有两个 ID、没有 Ka/Ks 值的行。程序只看进程退出码和文件是否存在，仍标为成功。
- **实测**：向真实 WGDI 流程注入 `yn00` 无结果的情况，得到只有 `A1\tA2` 的数据行；程序把 Ks 标为 `done`。随后恢复计算函数重试，该对基因因已经出现在旧文件中而完全不重算。
- **定位**：[状态重置](E:/ComparativeGenomicsAnalysisTool/app/wgdi/project.py:147)、[按存在性启用 Ks](E:/ComparativeGenomicsAnalysisTool/app/wgdi/pipeline.py:257)、[失败行写出](E:/ComparativeGenomicsAnalysisTool/dist/比较基因组分析/runtime/Lib/site-packages/wgdi/ks.py:110)、[旧对跳过](E:/ComparativeGenomicsAnalysisTool/dist/比较基因组分析/runtime/Lib/site-packages/wgdi/ks.py:72)。
- **建议**：Ks 结果与序列、共线性输入、算法设置绑定；校验有效数值行和成功/失败基因对数；只缓存真正成功的计算，失败对允许重试。

### A06：界面同名参数被覆盖

- **触发**：在“点阵图”页修改 score，或在“建库与比对”页修改 evalue；其他页面保留旧值。
- **实测**：界面 score 改为 777，evalue 改为 `1e-30`；执行 `apply_to()` 后实际参数仍是 score=100、evalue=`1e-5`。隐藏的“共线性”页同名字段在遍历时覆盖了前面页面的设置。
- **定位**：[参数汇总](E:/ComparativeGenomicsAnalysisTool/app/ui/analysis.py:734)。
- **建议**：共享参数使用唯一数据源，界面控件双向同步；或明确拆成每一步独立参数，避免按页面顺序覆盖。

### A07：最长转录本选择会优先选无 CDS 的长转录本

- **触发**：同一基因有一个 99 bp CDS 的编码转录本，以及一个跨度 900 bp、没有 CDS 的转录本。
- **实测**：`choose_longest()` 选择了没有 CDS 的转录本。自动提取随后跳过它，使本来有可用编码转录本的基因没有蛋白输出；极端情况下整批报“没有提取到任何 CDS”。
- **定位**：[排序规则](E:/ComparativeGenomicsAnalysisTool/app/prep/gff3.py:168)。
- **建议**：优先在具有 CDS 的转录本中比较 CDS 长度；仅当整个基因没有编码转录本时，进入明确的非编码处理分支。

### A08：GFF3 行顺序、多 Parent 处理错误

- **行顺序实测**：同一组合法特征，仅把 CDS 放在 mRNA 前面，转录本的所属基因从 `g1` 变成 `t1`，起点变成 0。CDS 暂存结果在文件末尾覆盖了后面已经解析的 mRNA 对象；CDS-only 反推也存在起点 0 的问题。
- **多 Parent 实测**：`Parent=t1,t2` 的共享 CDS 仅分配给 t1；预期两者 CDS 都为 30 bp，实际为 t1=30、t2=0。
- **影响**：合法注释的等价表示得到不同基因数、转录本选择和序列；也可能造成零坐标或丢失编码信息。
- **定位**：[仅取第一个 Parent](E:/ComparativeGenomicsAnalysisTool/app/prep/gff3.py:70)、[暂存结果覆盖](E:/ComparativeGenomicsAnalysisTool/app/prep/gff3.py:132)。
- **建议**：按 ID 建立并合并父子特征，解析结束后统一关联，正确支持多个 Parent；坐标用实际最小/最大 CDS 坐标初始化。优先评估成熟注释解析工具或库。

### A09：CDS phase 被忽略

- **触发**：部分 CDS 的转录方向首段 phase 为 1 或 2。解析器读取该列后丢弃，翻译始终从所提取序列第一个碱基开始。
- **实测**：`AATGAAATAG`、首段 phase=1，正确阅读框应翻译为 `MK*`；程序输出 `NEI`。
- **定位**：[phase 读取后未保存](E:/ComparativeGenomicsAnalysisTool/app/prep/gff3.py:95)、[未校正阅读框即翻译](E:/ComparativeGenomicsAnalysisTool/app/prep/build.py:184)。
- **建议**：按转录方向处理初始 phase，校验拼接阅读框及蛋白/CDS 一致性；不能简单删除每个 CDS 片段的 phase 个碱基。

### A10：手动模式输出重复基因 ID

- **触发**：蛋白 FASTA 有同一基因的两个不同转录本 ID。原始 FASTA ID 不重复，因此现有检查放行；归一化成基因 ID 后发生重复。
- **实测**：输入 `t1`、`t2` 均属于 g1，输出 `>g1 t1`、`>g1 t2` 两条蛋白；GFF 和报告却只有一个基因，无错误提示。WGDI 的 `SeqIO.to_dict()` 无法接受重复键。
- **定位**：[两个映射均保留](E:/ComparativeGenomicsAnalysisTool/app/prep/build.py:269)、[统一重写蛋白](E:/ComparativeGenomicsAnalysisTool/app/prep/build.py:308)。
- **建议**：每个基因明确保留一个一致的转录本，或在归一化前拒绝多转录本输入；最终检查 GFF、蛋白、CDS 的 ID 唯一性与对应关系。

### A11：手动模式未同步过滤注释和序列

- **实测**：开启默认过滤后，程序报告排除 `scaffold1`，长度表确实不再包含它；GFF 中仍有 scaffold1 上的 g2，蛋白中仍有 g2。
- **影响**：被排除的序列仍进入搜索库和比对；预处理计数及文件集合也不一致。是否改变某一份实际共线性结果取决于其命中和过滤情况，尚未对历史数据追溯。
- **定位**：[仅过滤长度记录](E:/ComparativeGenomicsAnalysisTool/app/prep/build.py:240)、[未按保留染色体筛选 choices](E:/ComparativeGenomicsAnalysisTool/app/prep/build.py:283)。
- **建议**：用同一份保留基因集合生成 GFF、长度、蛋白与 CDS。

### A12：不规则换行导致错误随机读取

- **触发**：一个 FASTA 序列内部有短行，后面又恢复正常行宽。当前索引只检查后续行是否比首行更长，不能识别该情况。
- **实测**：序列行依次为 `AAAAAA`、`CC`、`GGGGGG`、`TT`，读取第 9–10 位应得到 `GG`，实际得到 `G`；无警告，`needs_rewrap()` 返回否。
- **定位**：[行宽检查](E:/ComparativeGenomicsAnalysisTool/app/prep/fai.py:126)、[基于固定行宽定位](E:/ComparativeGenomicsAnalysisTool/app/prep/extract.py:69)。
- **建议**：索引时校验只有末行可以短于固定行宽，其他不规则换行先重排；提取后校验返回长度与请求区间一致。

### A13：预处理续跑漏查必需输出

- **实测**：项目标记预处理完成，但只保留 `A.gff`，A 的长度/蛋白/CDS 以及 B 的文件均不存在；续跑依然跳过预处理。
- **定位**：[预处理输出清单](E:/ComparativeGenomicsAnalysisTool/app/wgdi/pipeline.py:151)。
- **建议**：按比较模式和输入模式，核对两物种所有必需产物，并校验结构及运行版本。

### A14：Circos 导出格式选择不生效

- **实测**：在全流程 Circos 页只选 SVG，取消 PDF、PNG；实际导出调用仍是 PDF、PNG，不包含 SVG。
- **定位**：[界面选项](E:/ComparativeGenomicsAnalysisTool/app/ui/analysis.py:556)、[固定导出格式](E:/ComparativeGenomicsAnalysisTool/app/wgdi/pipeline.py:544)。
- **建议**：把全流程输出格式写入项目并传给导出器。此问题针对全流程页面；“仅绘图”页有单独的格式传递逻辑。

### A15：Ks 点阵 tandem 参数无效

- **实测**：配置 `tandem=false` 后，当前内置 WGDI 对象里的值仍是字符串 `'false'`，与 `False` 的比较不成立，移除分支不执行。同时构造器把 `remove_tandem` 方法覆盖为布尔值，存在另一处实现错误。
- **定位**：[方法被覆盖](E:/ComparativeGenomicsAnalysisTool/dist/比较基因组分析/runtime/Lib/site-packages/wgdi/block_ks.py:32)、[移除条件](E:/ComparativeGenomicsAnalysisTool/dist/比较基因组分析/runtime/Lib/site-packages/wgdi/block_ks.py:117)。
- **建议**：评估并固定 WGDI 的已验证版本或补丁；修正布尔解析及方法/字段同名问题，为两种 tandem 设置加入结果级测试。

### A16：MAFFT 指向无效的 Linux 路径

- **实测**：内置 WGDI 的有效 `mafft_path` 仍为 `/home/sunpc/micromamba/envs/wgdi/bin/mafft`，本机不存在该路径。应用没有发现、传入 Windows MAFFT 路径，也没有禁用该选择。
- **定位**：[界面的 MAFFT 选择](E:/ComparativeGenomicsAnalysisTool/app/ui/analysis.py:541)、[仅配置 MUSCLE 等路径](E:/ComparativeGenomicsAnalysisTool/app/wgdi/pipeline.py:264)、[内置调用](E:/ComparativeGenomicsAnalysisTool/dist/比较基因组分析/runtime/Lib/site-packages/wgdi/ks.py:146)。
- **建议**：检测实际可用的 MAFFT，写入其真实路径并验证版本；工具不可用时禁用选项并给出原因。

## 补充界面缺口

通过当前 UI 的调用路径检查，还确认**没有将已有分析项目加载回分析向导的入口**。项目区的选择按钮只选父目录；新建逻辑使用 `Project.create()`，遇到已有非空目录会生成带时间戳的新项目。现有 `Project.load()` 的 UI 调用用于结果窗口或载入绘图，并不恢复分析向导状态。此项是代码路径检查结论，未计入上面的 16 类、21 个动态复现场景。

因此，上轮答复中“重新打开程序和原项目，在点阵图运行本步”的说明需要更正：当前界面缺少“打开已有分析项目”的实现，重启后不能直接按该说明续跑；应补齐该入口及相应的状态恢复校验。
